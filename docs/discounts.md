# Discount Engine Overview

The new discount subsystem runs on Prisma against the Supabase Postgres cluster. Core tables live in the dedicated `discounts` schema and are created via Prisma migrations from the repository root.

## Database & Prisma

- The Prisma datasource uses `DATABASE_URL` with `sslmode=require`; configure it in your local `.env` before running migrations.
- Migrations live under `prisma/migrations/**`. To apply the latest schema locally:
  ```bash
  pnpm prisma migrate dev
  pnpm prisma generate
  ```
- Identifiers are UUIDs generated by `gen_random_uuid()`; monetary values are stored in cents (`Int`).
- Usage counters are tracked through the `discounts.CouponRedemption` table (with an optional `coupon_id`) and are enforced inside the new cart pricing transaction.

## API routes

All handlers sit in `apps/web-next/app/api`:

- `POST /api/admin/discounts` & `PUT /api/admin/discounts/:id` accept the payload validated by `DiscountInputSchema`.
- `POST /api/pricing/preview` performs a read-only quote for the supplied items.
- `POST /api/cart/price` shares the same shape but, when `commit=true`, runs a serialised transaction that locks the affected discounts/coupons and persists redemptions.

Admin routes reuse the existing guard and require the `staff`/`admin` Supabase roles.

## Admin UI

The CRUD interface lives under `apps/web-next/app/admin/(protected)/discounts/**` and uses the shared admin layout primitives. The form component (`_components/discount-form.tsx`) mirrors the API schema and manages assignments, exclusions and coupon rows inline.

## Tests

Basic engine coverage is included in `apps/web-next/tests/discounts/evaluator.test.ts`. Run the suite with:

```bash
pnpm vitest
```

The test config is pre-wired with the correct path aliases (`@`, `@shared`, `@ui`).
