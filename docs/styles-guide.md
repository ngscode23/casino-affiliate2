# Стиль-гайд по стилям (Tailwind, CSS-модули, inline)

Цель — минимизировать конфликты между Tailwind, CSS-модулями и inline‑стилями и упростить сопровождение.

## Приоритеты источников стилей

- **Tailwind** — основной инструмент для layout и типографики.
  - Используем для: `flex`, `grid`, `gap`, `px/py`, `w/h`, `max-w`, `text-*`, `font-*`, `bg-*`, `border-*`, `shadow-*`, `rounded-*`, состояний `hover/focus`, анимаций.
  - Для условных классов всегда используем `cn(...)` из `@shared/lib/cn` (он уже подключает `tailwind-merge`).

- **CSS-модули** — только там, где Tailwind не подходит:
  - сложные `@keyframes`, `content-visibility`, `contain`, `backdrop-filter`, `:has`,
  - сложные `box-shadow`, продвинутые `@media`, «портированные» витринные блоки (например, `SiteHeader`, карточки/грид продуктов),
  - работа с кастомными CSS‑переменными, которые трудно выразить утилитами.

- **Inline-стили** — только для динамических значений:
  - проценты и размеры, зависящие от данных (`width: ${percent}%`, высота колонок и т.п.),
  - runtime‑градиенты (`backgroundImage: gradient`),
  - проброс CSS‑переменных (`style={{ "--vc-card-width": "300px" }}`), которые далее читаются в CSS.

## Правила для компонентов

- На **одном и том же элементе** стараемся иметь один главный источник стилей:
  - либо `className={styles.vcCard}` (CSS‑модуль),
  - либо плотный Tailwind (`className="bg-card text-fg px-4 py-2 ..."`);
  - не дублируем одни и те же свойства в Tailwind и CSS‑модуле.

- Inline‑стили не дублируют то, что уже описано в CSS:
  - если свойство можно выразить в модуле / Tailwind, держим его там;
  - inline оставляем только для значений, которые реально меняются в рантайме.

- Сетка/карточки (`ProductCard`, `ProductGrid`):
  - **внешние обёртки** на страницах — Tailwind (`section`, контейнеры, отступы, фон),
  - **внутренний визуал карточек/скелетонов** — CSS‑модули и CSS‑переменные (`--vc-*`),
  - Tailwind‑классы не вешаем на те же элементы, где уже висит «богатый» класс из `.module.css`, если они трогают те же свойства (цвет, фон, отступы).

## Токены темы и цвета

- Для `apps/web-next` токены (`--bg-rgb`, `--fg-rgb`, `--card-rgb` и т.п.) описаны в:
  - `apps/web-next/app/globals.css` — для Next.js v4 и стилей приложения,
  - а также в `tailwind.config.ts` в `addBase` — для общих tailwind‑утилит и других приложений.
- При изменении цветовой темы:
  - обязательно проверяем и `globals.css`, и `tailwind.config.ts`, чтобы значения были синхронизированы;
  - в новых компонентах цвета берем только через токены (`bg-bg`, `bg-card`, `text-fg`, `text-muted`, `border-border`, `shadow-soft`), а не жёсткие hex/rgba, если это часть темы.

## Практические примеры

- `WishlistHeart`:
  - размер иконки управляется через проп `size` (inline‑style с `width/height`),
  - Tailwind используется только для кнопки‑контейнера (layout, фон, обводка, состояния).

- `ProductCard`:
  - layout, радиусы, шадоу и взаимодействие `Image` с `fill` контролируются CSS‑модулем + CSS‑переменными `--vc-*`,
  - inline‑стили используются точечно для совместимости с `next/image` (например, `inset`, `borderRadius`), без дублирования свойств, которые уже задаются в модуле.

## Новой код

Для новых компонентов придерживаемся простого правила:

- Сначала пробуем решить задачу Tailwind‑классами.
- Если Tailwind не позволяет удобно выразить нужный эффект — добавляем небольшой CSS‑модуль, в котором оставляем только то, чего нет в Tailwind.
- Если приходится использовать inline‑стили — по возможности прокидываем через CSS‑переменные, а не прямые `width/height/color`.
