Цель
Привести схему Postgres проекта аффилиат-сайта к состоянию V2, настроить RLS/политики для favorites (персонифицированный доступ через auth.uid()), подготовить заглушки auth.jwt()/auth.uid() для локалки, выполнить sanity-тесты (вставки/чтения как authenticated и service_role), проверить метрики кликов и собрать финальный отчёт.
Окружение

Postgres доступен (локально в Docker или удалённо через пулер).
Схема public уже содержит основные таблицы:
offers, clicks, impressions, favorites, partners, partner_offers, profiles.
RLS включён на: offers, clicks, impressions, favorites (если не включён — включить).
Подключение к БД предоставляется через переменные окружения (HOST/PORT/DB/USER/PASSWORD/SSL).

Предусловия (проверить/создать при необходимости)

Роли существуют (NOLOGIN): anon, authenticated, service_role.
Схема auth существует.
Для локалки (где Supabase функций нет) — есть заглушки:

auth.jwt() — читает request.jwt.claims и возвращает JSON (стабильно).
auth.uid() — парсит jwt.claims.sub и возвращает UUID; при невалидном sub — 00000000-0000-0000-0000-000000000000.


Таблица profiles(id uuid primary key) существует.
Вставить (если нет) тестовый профиль: id='00000000-0000-0000-0000-000000000001'.
На схему public и таблицу favorites даны права, чтобы дойти до RLS:

GRANT USAGE ON SCHEMA public TO authenticated, service_role
GRANT SELECT, INSERT, UPDATE, DELETE ON public.favorites TO authenticated, service_role


Индекс под «мои избранные»:
idx_favorites_user_created_at (user_id, created_at DESC) — создать, если отсутствует.

Нормализация favorites (RLS/политики)

Убедиться, что включён RLS на public.favorites.
Снести старые политики (favorites select own, favorites write own, favorites write service) — если есть.
Если функция auth.uid() доступна:
создать 2 политики:

favorites select own: SELECT для authenticated с USING (user_id = auth.uid())
favorites write own: ALL для authenticated с USING/WITH CHECK (user_id = auth.uid())


Иначе (нет auth.uid() — чистая локалка без Supabase):
создать единую политику favorites write service: ALL для service_role с (true) — только как временный режим локальной разработки.

Политики

Критерии приёмки

Политики favorites точно соответствуют режиму окружения:

Supabase/прод: favorites select own и favorites write own для authenticated.
Локалка без Supabase: одна favorites write service для service_role.


Вставка своей записи в favorites как authenticated — проходит.
Вставка чужой записи в favorites как authenticated — отвергается RLS.
service_role может вставлять клики (и favorites — если выбран сервисный режим).
Метрики отражают добавленный тест-клик.
EXPLAIN показывает использование соответствующих индексов.

Обработка ошибок

Если нет auth.uid() — автоматически включить сервисный режим для favorites и пометить в 99_summary.txt, что это локальный fallback.
Если FK favorites.user_id → profiles(id) блокирует тест-вставку — автоматически вставить профиль с id=auth.uid() в рамках транзакции теста (или откатить весь тест, зафиксировав причину в отчёте).
Если отсутствует оффер для теста — создать/обновить offers для slug='unknown' (или взять существующий test/lucky-star).
На каждом шаге — fail-fast с записью причины в отчёт.
